# Simquaro Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** deliver the standalone fictitious receiver, actionable `simquaro` CLI, controllable faults, and executable conformance evidence before implementing Synqaro Devices.

**Architecture:** one independently managed simulator process per configured instance; one shared receiver model with connection-local TCP framing/IDs. Validated immutable configuration is independent of its Python inventory loader. Test controls use a separate local Unix socket and typed fault catalog, never the hardware protocol.

**Tech Stack:** Linux with pidfds, Python 3.12+, `asyncio`, `decimal`/integer arithmetic, `dataclasses`, `argparse`, JSON, and `unittest`. Runtime has no third-party dependencies; packaging may use setuptools in an isolated build/development environment.

**Spec:** [Simquaro design](../specs/2026-10-28-simquaro-design.md); [Hardware Protocol](../../hardware_protocol.md) is authoritative for wire semantics.

**Execution:** approved by the user with subagents; use a new `codex/` branch in `/home/marco/repos/synqaro`, not a separate worktree. Preserve local progress and verify/review each task before its dependants.

## Global Constraints

- First configured instance is `receiver-a`, model `fictitious_receiver`, `127.0.0.1:9001`, initial verified 5 GHz, no initial faults. `all` selects the explicit inventory, not installed modules.
- Frequency range 1–10 GHz, 1 kHz grid, nearest/ties-up rounding after original-input range validation. Ten distinct rounded scan points; `dwell_ms` integer 1–1000.
- Hardware frames include LF within 4096 bytes; first-byte incomplete deadline 2000 ms; four pending requests per connection; independent increasing IDs 1–4294967295. Maximum 16 hardware clients.
- Client response/connect deadlines 2000 ms; failed-reconnect pause 5000 ms; default procedure polling 500 ms. No automatic modification replay or firmware reboot.
- Tuning limit 1000 ms, calibration limit 30000 ms, scan limit 20000 ms, additional controlled-stop limit 5000 ms. Normal tuning/stop 100 ms; calibration phases 1000/8000/1000 ms. No fabricated time-based progress.
- Private local runtime directory mode 0700; four control clients; control requests 8 KiB, responses 64 KiB, 2000 ms deadline; 64 scheduled rules. Local startup deadline 5 s; stop waits 2 s then forces termination and verifies within another 2 s.
- Flat instance names match `[a-z][a-z0-9_-]{0,47}`; `all` reserved. No arbitrary imports, method reflection, unsafe unlink, unverified PID kill, or general configuration hot reload.
- Use frozen validated configuration objects and a separate loader. Programmatic scenarios do not require files. Restart only the affected instance for startup-configuration changes; endpoint changes still require matching clients.
- Simulated firmware reboot changes `boot_id`, retains external injection conditions/rule counters, and loses unpromised procedure history; process restart reapplies only its initial scenario.
- Every user-facing error has a concrete corrective action; `stop` escalates without `--force`. Query success is distinct from simulated hardware health. Source docs remain English.
- No framework/plugin system, Device runtime/cache, NATS/database, scientific transfer, coupled system simulation, external configuration loader, or production communication library in this slice.
- Preserve unrelated changes. Implement on an isolated feature workspace, not directly on `main`. Publish/merge/issue closure only on the user's request to complete the step; local scoped commits provide progress checkpoints.

## Review Focus

- A foreground launcher interrupted during partial startup must not leave an owned child behind or kill a previously running instance; test in Task 7/8.
- A stale process record whose PID now belongs to an unrelated process must never cause signaling or socket theft; test in Task 7.
- A slow reader or indefinitely deferred response must not create an unbounded queue or block another client's status/control; test in Task 5/6.
- Changing a Python inventory or config object used by a test must not mutate an existing instance or require model knowledge of the loader; test in Task 1/4.
- Clearing a fault or rebooting must not turn an earlier unknown/failed/interrupted procedure into a fabricated success; test in Task 4/9.
